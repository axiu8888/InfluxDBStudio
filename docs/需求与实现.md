# InfluxDB Studio — 需求与实现逻辑

本文档描述当前分支相对原版 InfluxDB Studio 的产品范围、需求，以及对应实现。原版是面向 **InfluxDB 1.x / InfluxQL** 的 Windows 桌面管理工具（.NET Framework 4.6.1，WinForms）。

底层客户端为 `InfluxData.Net`。本工具**不支持** InfluxDB 2.x Flux / 3.x。

---

## 1. 产品定位与约束

### 1.1 要解决的问题

用图形界面管理 InfluxDB 1.x：连接、库、表（measurement）、查询、连续查询、保留策略、用户权限、导出结果。交互应对齐常见数据库管理工具（连接树 + 右侧工作区）。

### 1.2 InfluxDB 1.x 数据模型（决定 UI 挂在哪一层）

```
连接（服务器实例）
  └── 数据库（Database）
        ├── 保留策略 RP（属于库，不属于表）
        ├── 连续查询 CQ（属于库）
        └── 表 Measurement
              ├── Tag / Field / Series
              └── 点 Point（time + fields，挂在某条 series 上）
```

写入路径：`数据库.保留策略.表`。不写 RP 名时使用该库的 DEFAULT 策略。

由此得出的交互原则：

| 对象 | 挂载层级 | 原因 |
|---|---|---|
| 用户 / 诊断 / 统计 / 正在运行的查询 | 连接 | 实例级 |
| 保留策略、连续查询、回填、删库 | 数据库 | 库级 |
| Tag/Field/Series、删表/删序列 | 表 | measurement 级 |
| 查询编辑器 | 库或表 | 需要选定库；从表打开会预填 `FROM` |

InfluxDB **不能单独删除某个 field**，也没有 `ALTER CQ`。这些限制会直接体现在功能设计上（见第 5、6 节）。

## 2. 界面骨架

左侧 `TreeView` 三层节点：`Connection` → `Database` → `Measurement`。右侧 `ExtendedTabControl` 打开各类工作页。

选中节点后：

- 工具栏按钮按节点类型启用
- 右键菜单绑定在对应节点上
- 右键时先把该节点设为 `SelectedNode`，保证菜单操作作用在点击的节点上

主窗口启动时居中（`StartPosition = CenterScreen`）。

## 3. 连接与数据库列表

### 3.1 需求

- 连接只配置主机、端口、账号、SSL，**不再要求填写单个数据库**。
- 连接成功后列出该实例上的全部库。
- `_internal` 是 InfluxDB 系统库，默认不出现在树里；不允许从界面删除。

### 3.2 实现逻辑

1. `ConnectionDialog` 保存时将 `connection.Database = null`，表示列出全部库。
2. 刷新连接时调用 `SHOW DATABASES`（`GetDatabaseNamesAsync`）。
3. `InfluxDbHelper.IsInternalDatabase` 判断名称是否为 `_internal`：树节点跳过、删库按钮禁用。
4. 若用户手动指定了 `_internal`，仍可通过连接配置进入，但不作为常规列表项。

关键文件：`Dialogs/ConnectionDialog.cs`、`Data/InfluxDbHelper.cs`、`AppForm.cs`（`RenderDatabases`）。

## 4. 国际化（中英切换）

### 4.1 需求

- 界面、菜单、对话框、运行时提示支持 English / 中文。
- 切换语言后立即按新语言显示（实现上通过重启应用）。
- 设计器里的英文 `Text` 即翻译查找键；代码动态创建的菜单也必须能翻译。

### 4.2 实现逻辑

1. `Program` 启动最先调用 `Localization.ApplySavedCulture()`，根据 `Settings.Language`（空则跟 OS）设置 `CurrentLanguage` 和线程 Culture。
2. `Localization.ZhMap`：英文原文 → 中文。`T(text)` 在中文模式下查表，没有映射则原样返回。
3. 窗体/控件构造完成后调用 `Localization.Apply(this)`：递归翻译 `Control.Text`、ListView 列头、ToolStrip、以及通过反射拿到的 **私有** `ContextMenuStrip` 字段。
4. **必须先创建菜单再 Apply**。标签页右键菜单原先在 `Apply` 之后才 `new`，导致 Close / Close Other 一直是英文；现已改为创建后再 `Apply`。
5. 纯代码创建、且会反复重建的项（收藏/历史子菜单）直接 `Localization.T("Select")`，不依赖一次性 Apply。
6. 切换语言写入 Settings 后 `Application.Restart()`。

关键文件：`Localization.cs`、`Program.cs`、`Controls/ExtendedTabControl.cs`。

标签页菜单文案：`Close` / `Close Other` / `Close All`（中文：关闭 / 关闭其他 / 全部关闭）。

## 5. 查询编辑器

### 5.1 需求

- 从表打开查询时给出可用的默认 SQL。
- 大结果集不能把 UI 卡死：未写 `LIMIT`/`OFFSET` 的 `SELECT` 自动补上。
- InfluxQL 关键字、函数、表名、字段、标签可自动完成。
- 右键可美化/压缩 SQL。
- 查询可收藏、可看历史；执行成功后记入历史。
- 结果单元格居中；时间按本地时区 + 用户选定格式显示。
- 结果可导出 CSV / Excel / JSON。

### 5.2 实现逻辑

**默认 SQL**（从表打开）

```sql
SELECT * FROM "<measurement>" WHERE time > now() - 5m LIMIT 1000 OFFSET 0
```

**自动 LIMIT / OFFSET**（`InfluxDbHelper.EnsureSelectPaging`）

- 只处理以 `SELECT` 开头的语句。
- 已有 `LIMIT`/`OFFSET`、或带 `INTO` 的语句不改（`INTO` 是写回库，不能截断）。
- 缺省：`LIMIT 1000`、`OFFSET 0`。插入位置避开已有 `OFFSET`/`SLIMIT`/`SOFFSET`。
- 状态栏提示是否自动加过子句。编辑器里的原文不改，只改真正发给服务器的语句。

**自动完成**（`InfluxQlAutoComplete` + Scintilla）

- 根据光标前文本判断上下文：`SELECT` / `FROM` / `WHERE` / `GROUP BY` 等。
- 建议来源：关键字、函数、当前库的 measurement、当前 FROM 子句的 field/tag。
- 列表项带类型标签（字段/标签/函数/表/关键字）；选中后只插入名称。

**格式化**（`InfluxQlFormatter`）

- 美化：关键字换行、缩进。
- 压缩：单行。

**收藏与历史**（`QueryLibrary`）

- JSON 存在用户配置：`QueryFavoritesJson`、`QueryHistoryJson`。
- 收藏：可选名称；增删改。
- 历史：执行成功（分页请求发出）后写入；相同 SQL 提到最前；最多 50 条。
- 子菜单每次打开时重建，文案走 `T()`。

**时间显示**（`AppSettings.FormatValue` / `ToLocalDisplayTime`）

- Influx 存 UTC。若 `DateTimeKind` 为 Utc 或 Unspecified，转为本地再按 `DateFormat + " " + TimeFormat` 输出。
- 预置日期：`yyyy-MM-dd`、`yyyy/MM/dd`、`MM/dd/yyyy`、`dd/MM/yyyy` 等。
- 预置时间：`HH:mm:ss`、`HH:mm:ss.fff`、`HH:mm:ss.SSS`（内部当 `fff`）、`hh:mm:ss tt`、`HH:mm`。
- JSON 导出同样走本地时间，与列表一致。

**Excel 导出**（`ExcelExport.WriteXlsx`）

- 不引用第三方 Excel 库，按 Open XML 自己写 zip（`[Content_Types].xml` + `xl/worksheets/sheet1.xml`）。
- 查询结果、Tag Keys/Values、Field Keys、Series 列表均可导出。
- File → Export → Settings 仍是应用配置 JSON，不是表格。

关键文件：`Controls/QueryControl.cs`、`Controls/QueryResultsControl.cs`、`Controls/InfluxQlAutoComplete.cs`、`Controls/InfluxQlFormatter.cs`、`QueryLibrary.cs`、`AppSettings.cs`、`Controls/ExcelExport.cs`。

## 6. 连续查询（CQ）

### 6.1 需求

- 入口在**数据库**上，不在连接上：查看 / 新建 / 删除。
- 列表页支持编辑。InfluxDB 没有 `ALTER CQ`，编辑必须可落地。
- 从菜单新建/删除后，已打开的 CQ 页要刷新。

### 6.2 实现逻辑

菜单：`Continuous Queries → View / New / Delete`（连续查询 → 查看 / 新建 / 删除）。工具栏 CQ 按钮 = View。

**查看**：打开 `ContinuousQueryControl`，绑定当前库，执行 `SHOW CONTINUOUS QUERIES`。

**新建**：`CreateContinuousQueryDialog` 填参数 → `CREATE CONTINUOUS QUERY`。

**删除**：`SelectContinuousQueryDialog` 选出一条 → 确认 → `DROP CONTINUOUS QUERY`。

**编辑**（列表双击 / 工具栏 Edit CQ）：

1. 用 `LoadFromQuery` / `TryParseContinuousQuery` 把已有 CQ 文本解析回对话框。
2. 解析失败则提示无法编辑。
3. 因没有 ALTER：
   - 改名：先 `CREATE` 新的，成功后再 `DROP` 旧的；若 DROP 失败，提示新 CQ 已在、旧的还在。
   - 同名：先 DROP 再 CREATE（实现上按「创建新定义 + 删旧」组合，见 `ContinuousQueryControl.EditContinuousQuery`）。

菜单侧的新建/删除成功后调用 `RefreshOpenContinuousQueryTabs`，只刷新同一 `InfluxDbClient` + 同一数据库的已打开 CQ 页。

关键文件：`AppForm.cs`、`Controls/ContinuousQueryControl.cs`、`Dialogs/CreateContinuousQueryDialog.cs`、`Dialogs/SelectContinuousQueryDialog.cs`。

## 7. 保留策略（RP）

### 7.1 需求

- RP **不是全局的**，属于某个数据库；同一 RP 名在不同库互不影响。
- 入口必须在**数据库**上，与 CQ 一致：查看 / 新建 / 删除。
- 打开查看页时直接绑定当前库，不要再让用户从连接进页再切库。
- 可以真正 `DROP RETENTION POLICY`（会删掉该策略下全部数据）。
- 每个库至少留一条 RP；删掉 DEFAULT 后应指定另一条为默认（优先 `autogen`）。

### 7.2 实现逻辑

菜单：`Retention Policies → View / New / Delete`（保留策略 → 查看 / 新建 / 删除）。

连接右键不再出现「Show Retention Policies」。工具栏策略按钮仅在选中**数据库**时可用，位置与创建库 / CQ 一组。

**查看**

1. `ShowRetentionPolicies(node)` 取当前库名。
2. 新建 `RetentionPolicyControl`，设置基类 `RequestControl.Database`。
3. 标签标题：`{连接名}.{库名} policies`。
4. 控件不再列出全部库的下拉框，只显示当前库并 `SHOW RETENTION POLICIES ON <db>`。

**新建**

`RetentionPolicyDialog` → `CREATE RETENTION POLICY ... ON "<db>"`。若勾选默认，库不支持一次带 DEFAULT 时，再发 `ALTER ... DEFAULT`。

**删除**

1. 拉取该库全部 RP。
2. 0 条：提示没有可删的。
3. 仅 1 条：提示「每个数据库至少需要保留一条保留策略」，不弹出选择框（与页内 Drop 按钮 `Items.Count > 1` 一致）。
4. 多条：`SelectRetentionPolicyDialog` 选择 → 确认 → `DROP RETENTION POLICY "<name>" ON "<db>"`。
5. 若删的是默认策略，在剩余策略里找 `autogen`，否则取另一条，再 `ALTER ... DEFAULT`。
6. `RefreshOpenRetentionPolicyTabs` 刷新已打开的同库策略页。

页内工具栏 Create / Alter / Drop 仍可用，逻辑与菜单相同，只作用于当前页绑定的库。

对应 InfluxQL：

```sql
SHOW RETENTION POLICIES ON "db"
CREATE RETENTION POLICY "rp" ON "db" DURATION 7d REPLICATION 1 [DEFAULT]
ALTER RETENTION POLICY "rp" ON "db" DURATION 7d REPLICATION 1 [DEFAULT]
DROP RETENTION POLICY "rp" ON "db"
```

关键文件：`AppForm.cs`、`AppForm.Designer.cs`、`Controls/RetentionPolicyControl.cs`、`Dialogs/RetentionPolicyDialog.cs`、`Dialogs/SelectRetentionPolicyDialog.cs`、`Data/InfluxDataNetClient.cs`。

## 8. 明确不做 / 做不到的事

| 想法 | 结论 | 原因 |
|---|---|---|
| 选中表后增删 RP | 不做 | RP 属于库，表没有自己的策略 |
| 删除单个 field | 做不到 | 没有 `DROP FIELD`；只能 `SELECT INTO` 重写数据 |
| `ALTER CONTINUOUS QUERY` | 做不到 | 官方只有 CREATE / DROP，编辑走删建 |
| 连接级「管所有库的 RP」 | 已撤销 | 和数据模型不一致，已改到数据库菜单 |

## 9. 打包发布

### 9.1 需求

一键 Release 编译，打出可分发的绿色包（zip），不把 pdb/xml/log 打进去。

### 9.2 实现逻辑

仓库根目录：

```text
pack.cmd          双击或命令行入口
pack.ps1          实际脚本
```

流程：定位 MSBuild（vswhere + 常见 VS 路径）→ `nuget restore`（没有 nuget.exe 则下载到 `tools/`）→ `Rebuild Release` → 拷贝 `bin\Release` 中的 exe/dll/config → `dist/InfluxDBStudio-<文件版本>.zip`。

运行要求：目标机器有 **.NET Framework 4.6.1+**（Win10 通常已有）。

`dist/`、`tools/nuget.exe` 已加入 `.gitignore`。
